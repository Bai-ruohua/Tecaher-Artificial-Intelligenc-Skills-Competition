## 二、架构设计

### 2.1 认证分层

```
统一登录页 (/login)
    ├── 教师登录 → /teacher/dashboard
    └── 学生登录 → /student/dashboard

鉴权装饰器：
    @login_required    → 任何需登录的路由
    @teacher_required  → 教师端所有路由
    @student_required  → 学生端所有路由
```

### 2.2 数据关系（1对多）

```
teachers (1) ──< courses (N)
                    │
                    │ (1课程可有多学生)
                    ▼
              enrollments (N) >── students (N)
```

- 一个教师可创建多门课程
- 一门课程可包含多名学生（通过 enrollments 选课关系）
- 一个学生可同时选修多门课程（跨教师）

### 2.3 数据同步链路

```
学生答题 (student_attempts)
    → 触发 sync_student_data()
    → 计算5维能力雷达 (ability_scores)
    → 计算章节掌握甘特 (mastery_timeline)
    → 教师端 /api/teacher/dashboard 实时聚合展示
```

## 六、排名算法

```
综合得分 = 正确率×0.4 + 平均分×0.3 + 答题量归一化×0.2 + 学习时长归一化×0.1
```

- 答题量归一化：50题满分
- 学习时长归一化：300分钟满分
- 按综合得分降序排列，生成排名序号

## 七、甘特图数据源

每个章节一条记录：
- `mastery_level`: mastered(≥80%) / in_progress(≥60%) / weak(≥40%) / very_weak(<40%) / not_started
- `mastery_percent`: 正确率×100
- `start_date` / `end_date`: 首次答题 ~ 末次答题日期

前端用彩色进度条展示，绿=已掌握、蓝=进行中、橙=薄弱、红=很弱、灰=未开始。

## 十、技术质量把控要点（团队提升指导）

1. **分层清晰**：路由层（app.py）→ 业务逻辑层（modules/）→ 数据层（database.py），禁止跨层调用
2. **认证统一**：所有页面路由加 `@login_required`，API加角色装饰器，杜绝越权
3. **数据同步自动化**：学生答题后 `sync_student_data()` 自动触发，教师端无需手动刷新
4. **密码安全**：SHA-256 + 随机salt，明文密码不入库
5. **前端解耦**：Chart.js 通过CDN引入，仪表盘数据全部走 `/api/*` 接口，前后端分离
6. **可扩展性**：新增能力维度只需在 `ABILITY_DIMENSIONS` 数组加一项，雷达图自动适配
