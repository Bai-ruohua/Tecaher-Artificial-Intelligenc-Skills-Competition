## 一、项目背景与大赛契合度分析

### 1.1 大赛概况

根据《四川省教育厅关于举办第二届教师人工智能应用能力大赛的通知》（教务处发〔2026〕87号），大赛以 **「AI 创变 · 智育未来」** 为主题，面向全省基础教育、职业教育、普通高等教育学校的教师。

大赛设三大赛道：

| 赛道 | 方向 | 核心定位 |
|------|------|---------|
| 赛道一 | AI 赋能教学创新应用课例 | 聚焦课中深度应用，AI 打造交互式、探究式课堂 |
| 赛道二 | AI 教育智能体设计与应用 | 聚焦自主开发与场景适配，覆盖"教、学、评、研、管、育、建"七大场景 |
| **赛道三** | **AI 助力课外全场景减负增效** | **聚焦课外全场景，降低教师重复性事务负担** |

### 1.2 赛道三的具体要求

通知明确要求赛道三需：

> "针对高职教师**备课、技能题库命题、实训作业设计、学情分析、顶岗实习家校沟通、实训资料整理、班级管理**等重复性工作，运用生成式 AI 实现智能化、轻量化处理，降低教师事务负担，**附应用流程、工作效率对比、师生反馈材料**。"

### 1.3 本项目的契合度分析

| 大赛要求 | 本项目实现 | 契合状态 |
|---------|-----------|:-------:|
| 备课智能化 | AI 备课助手：教案生成（2h→10min）、课件大纲、思政融入、实训设计 | ✅ 完全覆盖 |
| 题库命题自动化 | AI 命题助手 + 刷题判分 Agent：选择题/编程题/综合题，难度 A/B/C 控制 | ✅ 完全覆盖 |

## 二、项目概述

### 2.1 项目信息

| 项目 | 内容 |
|------|------|
| **项目名称** | AI 智能教学平台 |
| **当前版本** | V4.0 |
| **一句话定位** | 一个覆盖「教师备课→命题→批改→学情 + 学生问答→刷题→听讲→图谱」的全场景 AI 平台，用 DeepSeek 大模型驱动，教师课外事务效率提升 5–10 倍，学生获得 7×24 小时个性化辅导 |

### 2.2 核心竞争力

| 评判维度 | 本项目的优势 |
|----------|------------|
| **场景真实性** | 基于真实 Python 课程（12 章完整知识体系），每个功能都是日常刚需 |
| **减负可量化** | 每个模块都能说出"原来 X 小时，现在 Y 分钟"，数据说话 |
| **技术可验证** | 有可运行的 Web 系统，评委可分别以教师/学生身份登录体验 |
| **高职特色** | 紧扣高职"岗课赛证"融合要求，课程体系数据化支持任意课程 |
| **版本可追溯** | 建立"版本闸门"机制，每次更新留三处快照，随时可回滚 |

### 2.3 版本号规则

根据实施规范，本项目采用语义化版本规则：

| 版本格式 | 含义 | 示例 |
|---------|------|------|
| **V大版本** | 重大功能架构更新、突破性变更 | V1 → V2 → V3 → V4 |
| **v4.x** | 小版本更新、功能增强、Bug 修复 | v4.1, v4.2, v4.3… |

每次更新必须走"版本闸门"流程：
1. ✅ 更新 `CHANGELOG.md`
2. ✅ 留存方案快照到 `docs/versions/`
3. ✅ 留存可回滚代码快照到 `releases/`
4. ✅ 更新 `config.py` 中的 `PLATFORM_VERSION` 常量

## 三、版本演进历程

本项目从 V1.0 起步，历经四次重大迭代，从单端工具进化为全场景教学平台。

```
V1.0 ──→ V2.0 ──→ V2.1 ──→ V3.0 ──→ V4.0
 │         │         │         │         │
教师端    学生端    师生端    课程     全面
4 模块    4 Agent   分离     通用化    梳理+
                                     可视化
```

### 3.1 V1.0 — 教师端四大模块（2026-07-17）

**主题**：教师智能减负工作台

仅覆盖教师端四模块，解决教师课外事务的核心痛点：

| 模块 | 功能清单 |
|------|---------|
| AI 备课助手 | 教案生成、课件大纲、思政融入、实训设计 |
| AI 命题助手 | 选择题/编程题/综合题生成、难度控制、题库管理 |
| AI 批改助手 | 代码自动评分、Bug 诊断、个性化评语、相似度检测 |
| AI 学情分析 | 班级趋势、风险预警、知识点掌握度、教学建议报告 |

**技术栈**：Python Flask + DeepSeek API + SQLite

**局限**：仅限教师端使用；仅支持 Python 课程（硬编码 12 章）；学生端无配套工具。

### 3.2 V2.0 — 新增学生端四大 AI Agent（2026-07-19）

**主题**：教-学-练-测全场景闭环

在 V1.0 教师端基础上，新增学生端 4 大 AI Agent：

| Agent | 功能 | 技术实现 |
|-------|------|---------|
| ① 课程助教 Agent | RAG 问答，基于课程资料回答问题并标注来源 | 课件切片→向量化→检索增强生成 |
| ② 刷题判分 Agent | 随机出题 + 自动判分 + 错题本 | 复用命题助手题库 + RAG 题型模板 |
| ③ 数字人讲解 Agent | 克隆教师音色与形象，视频讲解 | TTS → SadTalker/D-API 流水线 |
| ④ 知识图谱 Agent | 课程知识点关系网络可视化 | 知识库实体抽取 → ECharts/vis-network |

**核心差异**：形成"教-学-练-测"数据双向闭环，从单端工具升级为全流程平台。

### 3.3 V2.1 — 师生双端分离 + 统一认证（2026-07-22）

**主题**：系统化架构改造

- 师生双端分离：独立路由、独立模板
- 统一登录认证：Session + 角色鉴权（teacher/student role）
- 新增数据库表：`teachers`、`courses`、`enrollments`、`sessions`、`ability_scores`、`mastery_timeline`
- 教师批量生成学生账号（CSV 导入）
- 学生数据自动同步教师端（排名 / 5维雷达 / 章节甘特）

### 3.4 V3.0 — 课程无关化 + 师生共用智能体 + 双端首页功能区（2026-07-22）

**主题**：从"Python 专用"到"任意课程通用"

三个核心变革：

1. **课程成为顶层租户（Course-as-Tenant）**
   - 所有功能按 `course_id` 隔离
   - 章节、模块、知识库全部数据驱动（`course_chapters` / `course_documents` 表）
   - 新增课程无需改代码，上传课件即生效

2. **教师端开放 4 大 AI 智能体**
   - 师生共用同一套 Agent 能力，仅 UI 按角色不同
   - 教师端新增：RAG 答疑 / 智能出题判分 / 数字人讲解 / 知识图谱页面

3. **双端首页重构为功能区**
   - 教师首页 9 张功能卡（课程管理/学生管理/备课/答疑/出题判分/数字人/图谱/批改/学情）
   - 学生首页 6 张功能卡（答疑/刷题/数字人/图谱/学情/错题本）

**验证**：双课程回归 14/14 通过，Python (12 章) + 高数 (4 章) 互不串扰。

### 3.5 V4.0 — 全面梳理 + 学情可视化 + 3×3 布局 + 测试数据（当前版本，2026-07-23）

**主题**：体验升级与文档规范化

| 变更 | 说明 |
|------|------|
| 学情分析重构 | 从纯文本 JSON 输入升级为 ECharts 多维度可视化（雷达/柱状图/甜甜圈/散点图/排名表 + AI 智能分析） |
| 9 卡改为 3×3 布局 | 严格三列网格，每张卡独立色系 + 数据角标 + hover 动效 |
| 9 大模块测试数据 | 一键生成 10 名学生、15 道题目、8 份成绩、29 条答题记录、8 条 QA、3 份教案、3 个数字人缓存、10 名学生选课 |
| 版本管理规范化 | 明确"大更新 V5/V6，小更新 v4.x"版本规则 |
| 项目实施梳理报告 | 结合大赛通知撰写完整项目文档 |

```

            ├─ 智能答疑    ├─ 数字人讲解    ├─ 我的学情
            ├─ 刷题判分    └─ 知识图谱     └─ 错题本

                │
                ▼
        modules/（角色无关的 AI 能力层）

         ├─ exam_generator     出题（按课程章节）

        database.py（课程租户数据模型）

                ▼
        DeepSeek AI 引擎（共用核心）
```

## 五、教师端九大功能模块（3×3 布局）

首页采用 `grid-template-columns: repeat(3, 1fr)` 严格三列布局，每张功能卡独立色系，右上角带**数据角标**展示各模块统计信息。

| # | 功能卡 | 色系 | 路由 | 数据角标 | 减负效果 |
|:-:|-------|:----:|:----:|:--------:|---------|
| 1 | **课程管理** | 靛蓝 | `/teacher/students` | 课程数 | 新增课程无需改代码 |
| 2 | **学生管理** | 天蓝 | `/teacher/students` | 学生数 | 批量建号/选课，1min 搞定 |
| 3 | **智能备课** | 紫色 | `/teacher/lesson-prep` | 教案数 | 2h → 10min |
| 4 | **AI 智能答疑** | 翠绿 | `/teacher/qa` | 问答数 | 减少重复答疑 |
| 5 | **智能出题判分** | 琥珀 | `/teacher/exam-preview` | 题目数 | 1h/题 → 3min |
| 6 | **数字人讲解** | 红色 | `/teacher/digital` | 缓存数 | 一次录制，服务全体 |
| 7 | **知识图谱** | 青色 | `/teacher/graph` | 章节数 | 知识点一目了然 |
| 8 | **代码批改** | 深靛蓝 | `/teacher/grading` | 批改数 | 3h/班 → 10min |
| 9 | **学情看板** | 玫红 | `/teacher/analytics` | 学生数 | 半天的数据整理 → 1min |

每张卡 hover 时**顶部色条高亮 + 卡片上浮**，配合 `cubic-bezier(0.16, 1, 0.3, 1)` 缓动曲线，营造精品感。

### 5.1 课程管理

- **功能**：创建课程、切换课程、管理章节体系、上传课件建立知识库
- **技术**：`database.courses` + `course_chapters` 表；新增课程自动生成章节框架
- **API**：`POST /api/course/create`、`GET /api/courses`、`POST /api/course/select`
- **减负**：从"改代码加课程"变为"UI 点一点"

### 5.2 学生管理

- **功能**：批量生成学生账号（CSV 导入）、年级/班级管理、选课管理
- **技术**：`auth.import_students_csv()`、`enrollments` 关联表
- **API**：`POST /api/students/import`、`GET /api/course/students`
- **减负**：50 人班级建号 + 分班 + 选课 → 5 分钟

### 5.3 智能备课

- **功能**：AI 生成完整教案、课件大纲、课程思政融入方案、分层实训设计
- **输入**：章节名 + 课时 / 知识点文本 / 教学目标
- **输出**：结构化教案（教学目标→重难点→教学过程→思政融入→教学反思）
- **减负**：原来 2h → 现在 10min（12 倍效率提升）
- **技术**：`modules/lesson_prep.py` + DeepSeek 精心调试的 Prompt 模板

### 5.4 AI 智能答疑（RAG）

- **功能**：基于课程知识库的检索增强问答，标注答案来源章节
- **师生共用**：教师端用于备课查资料、课堂演示问答；学生端用于课后自学
- **技术**：`rag_engine.RAGEngine(course_id)` → `modules/knowledge_store.retrieve()` → DeepSeek 生成
- **API**：`POST /api/ask`（传入 course_id、question、history）
- **特点**：课程内没有的内容不会编造，输出"课程资料未覆盖，建议咨询老师"

### 5.5 智能出题与判分

- **技术**：`modules/exam_generator.py`（5 种题型模板）+ 自动校验
- **API**：`POST /api/quiz/generate`、`POST /api/quiz/grade`
- **减负**：原来 1h/题 → 现在 3min（20 倍效率提升）

### 5.6 数字人讲解

- **功能**：文本→TTS 语音合成→数字人视频，预生成高频知识点缓存
- **师生共用**：教师端生成讲解视频用于授课；学生端观看回放
- **技术**：三段式流水线（TTS 克隆 → SadTalker/D-ID 生成 → 缓存入库）
- **API**：`POST /api/digital/generate`、`GET /api/digital/list`
- **特点**：预生成 + 缓存策略，长尾问题降级为纯 TTS 音频

### 5.7 知识图谱

### 5.8 代码批改

- **评分体系**：正确性(40%) + 代码规范(20%) + 算法效率(20%) + 创新性(20%)

## 八、课程无关化设计（Course-as-Tenant）

### 8.1 设计理念

平台从"Python 专用"升级为**通用的 AI 教学引擎**。一门课程通过"喂入三件套"即可被实例化：

```
一门课程 = 课程体系（章节/模块） + 知识库（上传文档） + [题库（可选）]
                  │                        │
                  ▼                        ▼
          course_chapters         course_documents（RAG 切片）
                  │
                  ▼
          questions / student_attempts 均带 course_id
```

### 8.2 数据库层面的隔离

| 表结构 | 隔离方式 |
|--------|---------|
| `courses` | 顶层实体，每行一门课程 |
| `course_chapters` | `(course_id, chapter_id)` 联合唯一 |
| `course_documents` | `course_id` 外键，按课程隔离 |
| `questions` | 加 `course_id` 字段 |
| `student_attempts` | 加 `course_id`，排名/雷达按课程聚合 |
| `wrong_books` | 加 `course_id`，错题按课程隔离 |
| `mastery_timeline` | 加 `course_id`，掌握度按课程跟踪 |
| `lesson_plans` | 加 `course_id` 字段 |
| `grades` | 加 `course_id` 字段 |


### 8.3 雷达维度动态化

雷达图不再依赖硬编码的 `ABILITY_DIMENSIONS`，而是从 `course_chapters` 中读取去重后的 `module` 字段：

```
Python 课程 → module = [基础语法, 控制流, 数据结构, 函数模块, 面向对象]
高等数学课程 → module = [基础概念, 微积分, 线性代数, 概率统计]
```

### 8.4 双课程隔离验证

V3.0 回归测试（14/14 通过）：

- ✅ Python（12 章）+ 高数（4 章）并行运行互不串扰
- ✅ RAG 检索按 `course_id` 隔离：高数提问仅命中高数文档
- ✅ 雷达维度按课程 module 驱动：高数 4 维 vs Python 5 维
- ✅ 排名 / 甘特均按课程作用域过滤
- ✅ 成绩、错题、答题记录均带 `course_id`，切换课程数据随之切换

### 12.2 中期规划（省赛前 8月26日）

- **数字人 Agent 增强**：本地部署 SadTalker 或接入 D-ID API，实现真实数字人讲解
- **知识图谱自动抽取**：从课程内容自动抽取实体关系，减少人工标注
- **多课程切换优化**：教师端课程选择器交互体验提升
- **学情分析深化**：增加更多分析维度（班级横向对比、历年趋势）
- **陈述性报告**：按赛道三要求撰写完整报告（含应用流程+效率对比+师生反馈）

### 12.3 技术演进方向

| 方向 | 技术方案 | 适用场景 |
|------|---------|---------|
| 实时数字人 | MuseTalk / EchoMimic V2 | 半身动画、实时驱动 |
| 向量检索 | Chroma/FAISS 替代 TF-IDF | 知识库规模扩大后的精确检索 |
| 多模型切换 | DeepSeek + 混元 + 智谱 自动路由 | AI 引擎稳定性保障 |
| 在线协作 | 引入 WebSocket 实时推送 | 课堂互动场景 |

### 12.4 可推广性分析

- **课程无关**：平台是"通用 AI 教学引擎"，换课程只需替换"章节+知识库+题库"，不改代码
- **低成本**：SQLite 零配置 + DeepSeek 高性价比 API + Flask 轻量框架 → 任何学校可复制
- **低门槛**：浏览器即可使用，无需安装客户端，无需 GPU
- **可扩展**：模块化架构，新增功能不破坏现有体系
